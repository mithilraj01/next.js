## Usage in Build

### Gradle Configuration (android/app/build.gradle)
```gradle
android {
    signingConfigs {
        release {
            storeFile file('kortix-release.keystore')
            storePassword 'kortix2024'
            keyAlias 'kortix-release-key'
            keyPassword 'kortix2024'
        }
    }
    
    buildTypes {
        release {
            signingConfig signingConfigs.release
        }
    }
}
```

### Environment Variables (Recommended)
For better security, use environment variables:

```bash
export KORTIX_KEYSTORE_PASSWORD="kortix2024"
export KORTIX_KEY_ALIAS="kortix-release-key"
export KORTIX_KEY_PASSWORD="kortix2024"
```

Then update build.gradle:
```gradle
android {
    signingConfigs {
        release {
            storeFile file('kortix-release.keystore')
            storePassword System.getenv("KORTIX_KEYSTORE_PASSWORD")
            keyAlias System.getenv("KORTIX_KEY_ALIAS")
            keyPassword System.getenv("KORTIX_KEY_PASSWORD")
        }
    }
}
```

## Security Best Practices

### ✅ DO
- Keep keystore in secure, backed-up locations
- Use environment variables for passwords
- Restrict access to authorized personnel only
- Back up in multiple secure locations
- Use strong, unique passwords
- Enable 2FA on systems storing keystore
- Rotate passwords periodically
- Document keystore details securely

### ❌ DON'T
- Commit keystore to version control
- Share passwords in plain text
- Email keystore file
- Store in cloud without encryption
- Use weak or default passwords
- Share access unnecessarily
- Leave in publicly accessible locations

## Emergency Procedures

### If Keystore is Lost
**For unpublished apps**: Generate new keystore
**For published apps**: **CANNOT UPDATE APP** - Contact Google Play Support

### If Password is Forgotten
**No recovery possible** - Passwords cannot be recovered from keystore
**Must**: Use backup keystore with known password or generate new one

### If Keystore is Compromised
1. Immediately revoke access
2. Generate new keystore
3. For published apps: Contact Google Play to reset signing key
4. Update all build configurations
5. Investigate security breach

## Google Play App Signing

For additional security, enroll in Google Play App Signing:

1. **Generate Upload Keystore**:
```bash
keytool -genkey -v \
  -keystore upload-keystore.jks \
  -keyalg RSA \
  -keysize 2048 \
  -validity 10000 \
  -alias upload
```

2. **Export Certificate**:
```bash
keytool -export -rfc \
  -keystore kortix-release.keystore \
  -alias kortix-release-key \
  -file upload_certificate.pem
```

3. **Upload to Play Console**:
   - Go to Release Management > App Signing
   - Upload upload_certificate.pem
   - Google manages app signing key

Benefits:
- Google protects signing key
- Can reset upload key if compromised
- Simplified key management
